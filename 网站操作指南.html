KING桑的网站操作指南

这份指南对应你的项目文件夹：E:\projects\github_web。

平时只需记住四步：改文件 → 保存 → 本机预览 → 双击“一键上传到GitHub.bat”。

  • 公开网站：https://stevenkingson.github.io/Kingson-zju-isee/
  • GitHub 仓库：https://github.com/StevenKingson/Kingson-zju-isee
  • 发布进度：https://github.com/StevenKingson/Kingson-zju-isee/actions

网站操作指南.html 可以双击，用浏览器阅读；不联网也能打开。网站操作指南.md 是这份指南的文字原稿。

1. 第一次编辑前，先找到文件

  1. 按键盘 Win＋E 打开文件资源管理器。
  2. 点击上方地址栏，输入 E:\projects\github_web，按回车。
  3. 在资源管理器顶部点击“查看 → 显示 → 文件扩展名”。如果是旧版 Windows，在“查看”选项卡勾选“文件扩展名”。这样能分清 index.md 和误存的 index.md.txt。
  4. 找到要改的 .md 文件，右键点击，选择“打开方式 → 记事本”。如果没有记事本，点击“选择其他应用”再选记事本。
  5. 改完按 Ctrl＋S 保存。刚刚改错且还没关闭记事本时，可以按 Ctrl＋Z 撤销。

Markdown（.md）就是带简单排版符号的文字文件，下面会给你可复制的例子。只改正文时，不需要改程序。

2. 修改现有网页

修改“关于”页

  1. 打开 docs/about/index.md。
  2. 把“正在学习”“平时喜欢”等占位文字改成自己的介绍。
  3. 保留行首的 #、##、-，它们分别表示大标题、小标题、列表。
  4. 按 Ctrl＋S。

修改主页标题和欢迎语

打开 docs/index.md，找到下面这两处，只改标签之间的文字：

<h1>KING桑の放课后茶会</h1>
<p class="home-description">下课了，来喝杯茶吧。<br>在这里，慢慢记录学习与生活。</p>

<br> 表示换行；保留 <h1>、</h1>、<p ...> 和 </p>。如果要同时修改浏览器标题和页眉的网站名称，再打开 mkdocs.yml，修改第一行 site_name: 后面的文字。

修改现有课程

例如，“大二 → 专业基础课程 → 信号与系统”对应：

docs/course/year2/foundation/signals-systems/index.md

在其中修改心得即可。找不到文件时，可以在 mkdocs.yml 里按 Ctrl＋F 搜索课程名称，后面的路径就是它的位置，前面补上 docs/。

大一“专业基础课程”的文件夹实际叫 hard，“专业必修课程”的文件夹叫 major，这是已有路径，沿用即可。每门课程与 overview.md 合订本是独立页面：改了单门课，不会自动改写合订本；需要两边一致时分别修改。

3. 常用文字、图片和公式格式

可以把下面的格式复制进文章，然后替换文字：

# 课程名称

这里写开头介绍。段落之间空一行。

## 上课体验

这是普通文字，**这是加粗文字**。

- 第一条心得
- 第二条心得

## 考核方式

1. 平时作业
2. 期末考试

[链接名称](https://example.com/)

每篇文章一般只放一个 # 大标题，下面的小节用 ##，更小的小节用 ###。

给文章添加图片

  1. 在这篇文章所在的文件夹中，新建 images 文件夹。
  2. 把图片复制进去，例如 images/experiment-1.png。
  3. 在文章需要显示图片的位置加入：
![实验结果截图](images/experiment-1.png)

这里的图片路径相对于当前 .md 文件。图片必须复制进项目，不能填写电脑上的 E:\... 路径；访问网站的朋友无法读取你电脑的文件。

建议使用简短的英文文件名，以后引用和移动更方便。

添加公式

行内公式：

电压满足 $U=IR$。

单独成行的公式，前后各空一行：

$$
H(s)=\frac{1}{RCs+1}
$$

4. 新增课程或追番日记

新增一门课程

以“大二 → 专业基础课程”新增课程为例：

  1. 打开 docs/course/year2/foundation。
  2. 新建文件夹，例如 my-new-course。
  3. 打开记事本，写好文章，点击“文件 → 另存为”。
  4. 保存到刚才的文件夹，文件名填写 index.md，“保存类型”选“所有文件”，编码选 UTF-8。确认文件没有变成 index.md.txt。
  5. 打开 mkdocs.yml，找到“大二”下面的“专业基础课程”。在该分类最后一门课下面加一行，与上一行的短横线对齐：
      - 信号与系统: course/year2/foundation/signals-systems/index.md
      - 我的新课程: course/year2/foundation/my-new-course/index.md

只新增第二行，保留原有课程。mkdocs.yml 中的路径从 docs 内部开始，因此不要再加 docs/ 前缀。缩进请用空格，与相邻行一致，不要按 Tab。

  1. 在 docs/course/year2/index.md 的对应课程列表中加入：
- [我的新课程](foundation/my-new-course/index.md) — 一句话简介。
  1. 按需更新学年总览和课程首页中的课程数量。本机预览能打开新课程后，再一键上传。

更新关于页的头像与联系方式

  • 换头像：把新图片放进 docs/assets/profile/，命名为 avatar-filled.png 并替换原文件。如果原图不是 PNG，可以保留其真实后缀，然后同步修改 docs/about/index.md 中头像的文件名。
  • 换微信二维码：用新的完整二维码图片替换 docs/assets/profile/wechat-qr.png，保持四周留白，避免影响扫码。微信按钮会在当前页弹出二维码。
  • 改 B站或 CC98 链接：打开 docs/about/index.md，找到对应按钮的 href="https://..."，只替换引号中的网址。网址末尾不要加中文逗号。
  • 写个人介绍：同一文件中找到 ## 关于我，修改其下方的文字。首屏保留头像和按钮，个人介绍会在向下翻页后显示。
  • 二维码和头像都是网站公开素材，更新后继续双击“一键上传到GitHub.bat”发布即可。

更新追番日记（封面卡片）

  1. 打开 docs/assets/anime/watchlist.json，右键 → 打开方式 → 记事本。这里集中保存番剧信息。
  2. 三个英文名称分别对应：watching = 正在追、planned = 打算补、recommended = 疯狂推。正在追里的 season 是季度名称，例如 2026年10月新番；每个季度的 anime 方括号里放这一季的番剧。
  3. 修改现有条目时，主要改下面这些值：
字段 怎么填写
id 不重复的简短英文名称，例如 my-anime
title 番剧名称，保留前后的英文双引号
cover 封面路径，例如 assets/anime/my-anime.jpg；把图片放进 docs/assets/anime/
coverFit 可选；写 "cover" 会铺满封面并裁掉两侧；不写这个字段则完整显示原图
status 正在追、打算补、疯狂推 或 已弃坑；弃坑时同时把 completed 设为 false
completed 看完写 true，未看完写 false；看完会显示“已看完”标签
review 评价文字；暂时不写则保留 ""；换行写 \n
score 0～10 的数字，例如 10、9.5；未评分写 null，数字不加引号
source 图片出处的完整网址
sourceName 出处名称，例如“动画官网”
  1. 新增番剧：复制同组里从 { 到对应 } 的完整条目，放进同一对方括号 [] 里面。两个条目之间加一个英文逗号 ,，最后一个条目后不加逗号。
  2. 新增季度：在 watching 方括号里复制现有的整个季度对象，修改 season，再修改这个季度 anime 里的番剧。季度按照文件中的顺序显示，建议把最新季度放在最前面。
  3. 从“打算补”移到“疯狂推”：把该番剧的完整条目剪切到 recommended，修改 status，把 completed 设为 true，然后写评价和评分。注意修正两边相邻条目之间的逗号。
  4. 保存文件，打开本机预览。点击封面应直接显示评价，再点一次或按 Esc 收起；页面不会跳转。
  5. 确认效果后双击根目录的“一键上传到GitHub.bat”。程序会检查清单和封面路径，并同步生成可搜索的文字目录；清单格式或图片路径有误时会停止上传。

封面建议从作品官网、电视台或发行方的官方作品页寻找。把图片下载到本机资源目录，并在 source 记录出处，之后不会因为外站禁止直接引用而突然消失。现有封面的来源记录在 scripts/anime-artwork-sources.md。

“打算补”下方的“推荐一部番”会打开仓库的 GitHub Issue 表单。访客需要登录 GitHub；你在仓库 Issues 查看推荐，再自行挑选加入清单。表单文件是 .github/ISSUE_TEMPLATE/anime-recommendation.yml。

信电导资料放在哪里

信息与电子工程导论位于 docs/course/year2/major-required/isee-introduction/。

  • 三次作业：reports/experiment-1/、experiment-2/、experiment-3/。网页正文在各自的 index.md；完整原稿与配图在 source/，打包下载在 source.zip；assignment.pdf 是题目，reference.pdf 是指导资料。
  • 期末课程设计：reports/course-design/index.md 是网页，report.pdf 是报告，formulas.md 是可复制的公式。
  • 自制模板：resources/report-template/，修改 template.md 时请同时更新 report-template.zip。
  • 修改作业原稿后，记得同步网页正文与 ZIP 下载包；上传前检查文字、截图和 PDF 是否含个人信息。

5. 添加或替换实验报告 PDF

现有报告都位于对应课程的 reports/ 下。例如：

docs/course/year2/labs/circuit-design-1/reports/experiment-2/

只替换现有 PDF

把新 PDF 复制到对应报告文件夹，使用与原文件完全相同的文件名并替换原文件。页面中的链接和预览会继续使用它。文章中写死的文件大小、页数或正文说明需要按实际情况修改。

新增一份报告

  1. 在该课程的 reports 内新建报告文件夹，如 experiment-new。
  2. 放入 report.pdf，新建 index.md。
  3. 在 index.md 中使用下面的格式：
# 我的实验报告

这里写实验简介。

[在线打开 PDF](report.pdf)

<details class="report-pdf" data-pdf="report.pdf">
  <summary>展开 PDF 预览</summary>
</details>
  1. 在该课程的 reports/index.md 加入新报告链接；需要显示在侧边菜单时，也在 mkdocs.yml 加入这份 index.md 的路径。

data-pdf 的文件名要与实际 PDF 一致。不要修改预览用的 class="report-pdf"，展开后就能翻页、输入页码和缩放。

6. 更新画集和 BGM

给现有画集加图

把新图片复制到 docs/assets/artbooks/k-on-2009-2012/，按已有编号继续命名，例如 424.jpg。同一画集不能出现重复编号，如 001.jpg 与 001.png 会被识别成同一个编号。

添加另一套画集

  1. 在 docs/assets/artbooks/ 新建文件夹，例如 another-artbook。
  2. 放入图片，建议使用 001.jpg、002.jpg 这样的编号。
  3. 如需显示中文画集名，在新文件夹内新建 album.json，复制下面的内容并修改文字：
{
  "title": "我的新画集",
  "description": "这里写画集简介"
}

重新启动预览或运行一键上传，程序就会刷新列表。新画集会出现在画集选择框中，也会参与首页随机背景。

添加歌曲

现在有两个独立歌单：轻音少女（20 首）、Vaundy（21 首）。点网页右上角的 ☷ 歌曲目录，在“选择歌单”中切换；歌曲目录和随机下一首都只针对当前歌单。浏览器会记住选择。播放中切换会继续播放，暂停时切换会保持暂停。

  • 给轻音少女歌单加歌：把 MP3 复制到 docs/assets/music/。
  • 给 Vaundy 歌单加歌：把 MP3 复制到 docs/assets/music/vaundy/。

重新启动预览或一键上传后，新歌曲会自动排在对应歌单末尾，名称默认使用文件名。Vaundy 歌单已按你的要求排除《Assumptions》，本机原始音乐文件夹保留。

添加独立的新歌单

  1. 在 docs/assets/music/ 下新建文件夹，例如 my-playlist。
  2. 将歌曲复制进去。文件夹会自动成为一个单独歌单，不会混进轻音少女歌单。
  3. 如果要自定义歌单名称，在该文件夹内新建 library.json，填入以下内容：
{
  "id": "my-playlist",
  "title": "我的新歌单",
  "tracks": []
}

id 不要与其他歌单重复。重新启动预览或上传，歌单会自动出现在选择框中。

修改现有歌曲名称、顺序或删除曲目

轻音少女使用 docs/assets/music/library.json，Vaundy 使用 docs/assets/music/vaundy/library.json。打开要修改的歌单配置，在 tracks 内编辑：

  • title：歌曲目录里显示的名称，可以修改。
  • artist：歌曲的演唱者，可选。
  • number：显示的编号；需要为正整数，同一歌单中不要重复。
  • 每个 { ... } 代表一首歌；这些条目的排列顺序就是目录顺序。
  • file：实际音频文件名，必须与文件夹中的文件一致。
  • 删除已登记歌曲时，同时删除对应的整条 { ... } 配置和 MP3 文件。JSON 的条目之间用逗号隔开，最后一条后面不加逗号。

playlist.json 是自动生成的，请改 library.json，不要直接改 playlist.json。如果修改后程序提示曲库配置错误，把日志中的报错发给我即可。

7. 处理友链申请和留言

查看、通过友链申请

  1. 打开仓库的 Issues，查看带“友链申请”标签的申请。
  2. 打开对方网站，决定是否收录。
  3. 打开 docs/friends/index.md，在“茶会的朋友”下面添加：
- [朋友的网站名称](https://example.com/) — 朋友网站的一句话介绍。

第一次加友链时，删除“这里的座位还空着……”这句占位文字。

  1. 保存、预览、一键上传。
  2. 网站更新后，在申请 Issue 中回复结果，处理完再关闭 Issue。

友链不会自动通过。页面上的申请表单在 .github/ISSUE_TEMPLATE/friend-link.yml 中；不需要改表单时不用动这个文件。

回复和管理留言

打开留言主帖，登录 GitHub 后回复访客。管理单条留言时，点击留言右上角的 … 菜单。

网页留言和 GitHub 主帖中的评论是同一份内容，新增留言不需要重新部署。docs/guestbook/index.md 只负责网页上方的介绍；不要把访客留言手动复制进去。

8. 本机预览，再一键上传

右上角图标旁有文字说明：“白天模式 / 夜间模式”表示当前主题，“播放 BGM / 暂停 BGM”表示点击后的音乐操作。主题按访客设备的本地时间自动切换：06:00–18:00 为白天，其余为夜间。也可以手动点击主题按钮，选择会保留到下个昼夜时段，然后恢复自动；页面一直打开时也会按时间更新。

第一步：检查修改效果

  1. 在项目根目录双击 start-preview.bat，保留打开的窗口。
  2. 打开浏览器，输入 http://127.0.0.1:8000/。
  3. 检查改过的文字、新增导航、图片和附件能否打开。
  4. 普通文章保存后通常会自动刷新。画集、曲库需要重新扫描时，点击预览命令窗口，按 Ctrl＋C，如果提示是否终止，输入 Y 并回车，然后重新双击 start-preview.bat。

第二步：上传

  1. 保存所有正在编辑的文件。
  2. 回到项目根目录，双击 一键上传到GitHub.bat。
  3. 等待程序依次检查项目、补齐依赖、更新画集和曲库、构建网站、保存版本并上传。
  4. 如果弹出 GitHub 登录，登录 StevenKingson，按提示完成验证。当前电脑已经登录时通常不需要这一步。
  5. 看到“上传成功”后，按任意键关闭窗口。

双击即开始上传，不需要再输入 Git 命令或逐次确认。它会包含项目内所有未被忽略的新增、修改和删除，因此这个文件夹请只放网站相关内容。

程序不会上传 site/、.venv/、__pycache__/、output/ 和日志。每次上传都会留下一个带时间的 Git 提交，方便以后查找版本。

第三步：等待公开网站更新

  1. 打开 GitHub Actions。
  2. 点击最新一条 Build and deploy website，等待 build 和 deploy 都出现绿色对勾。
  3. 打开公开网站，按 Ctrl＋F5 刷新。

上传成功表示代码已到 GitHub，公开网站还要等待 Actions 发布，通常需要几分钟。没有任何改动时，程序会提示“无需重复上传”；如果上次提交已保存但推送失败，再次双击会继续推送。

9. 常见问题怎么处理

看到的情况 怎样操作
文件变成 index.md.txt 开启“文件扩展名”，右键重命名为 index.md，确认更改扩展名。
导航配置报错、找不到页面 核对 mkdocs.yml 的空格缩进与路径；路径不用加 docs/，文件名要与实际文件一致。
图片在电脑上能看，上线看不到 检查图片是否已复制进 docs/；文章使用相对路径，不用本机磁盘路径。注意文件名大小写。
曲库提示 missing 或 duplicated 核对 library.json 的 file 是否与 MP3 文件名一致，编号是否重复。
单个文件超过 100 MiB 压缩图片/PDF/压缩包，或把大文件拆分，再双击上传；这是 GitHub 的单文件限制。
网络断开、登录失败、push 失败 保留文件，恢复网络或完成 GitHub 登录后再次双击。已经保存的本机提交不会丢失。
“GitHub 上有本机尚未包含的提交” 可能曾在 GitHub 网页或另一台电脑修改过。把提示发给我，我会帮你同步；程序不会自动覆盖远程内容。
“另一个上传窗口正在运行” 等待原窗口结束，再试一次。不要同时打开多个上传窗口。
程序显示构建失败 看窗口最后的具体报错；本次不会继续提交和上传。日志保存在 output/ 内，文件名以 upload- 开头。
上传成功，但网站还是旧内容 先确认 Actions 已出现绿色对勾，再按 Ctrl＋F5；如果 Actions 红色失败，打开那条记录查看失败步骤。

没有 Python 或 Git

当前电脑已经安装；通常只有换电脑时才会遇到。

  • Python：打开 https://www.python.org/downloads/windows/，建议安装与本项目一致的 Python 3.11，安装界面勾选 Add python.exe to PATH。完成后重新双击上传程序，它会自动建立 .venv 并安装网站依赖。
  • Git：打开 https://git-scm.com/downloads/win，安装 Git for Windows，通常保留默认选项即可。安装完成后关闭旧命令窗口，重新双击上传程序。
  • 换电脑需要先从仓库克隆项目（保留 .git），仅下载 ZIP 不包含 Git 版本记录，不能直接使用这个上传程序。

Git 提示没有提交身份

在项目文件夹的地址栏输入 powershell 并回车，依次运行：

git config user.name "StevenKingson"
git config user.email "在这里填写你的GitHub提交邮箱"

第二行先把双引号里的文字换成 GitHub Settings → Emails 中的邮箱；想隐藏真实邮箱时，可以复制该页面提供的 noreply 邮箱。这里只设置本项目，不修改其他仓库。

只检查，暂时不上传

在项目文件夹打开 PowerShell，运行：

.\.venv\Scripts\python.exe scripts\upload-github.py --check-only

它会刷新素材目录、操作指南并检查构建，但不提交或推送。

10. 哪些文件平时不需要动

  • site/、.venv/、output/：生成文件、运行环境和本机日志，不是文章原稿。
  • docs/assets/gallery.json、docs/assets/music/playlist.json：自动生成的目录，重新扫描会覆盖手动修改。
  • docs/javascripts/、overrides/：播放器、画集、PDF 预览等功能代码；只改文章时不用动。
  • docs/assets/giscus.json：已经接通留言主帖的配置，日常回复留言不用改。
  • scripts/import-course-notes.py：早期导入课程用的脚本，重新运行会覆盖生成的课程页面，日常编辑不要运行它。

这份指南的原稿是根目录的 网站操作指南.md。修改原稿后，一键上传程序会自动重新生成浏览器阅读版。
